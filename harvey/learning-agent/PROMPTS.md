> B01, 2026-11-02. START REGISTER. Here are today's emails from the legal intake mailbox. Produce the batch deliverables in the output format, create the Intake learning register artifact, and end with END OF BATCH B01.

## Every later day

Attach the day's emails, then send:

> B02, 2026-11-03. Here are today's emails from the legal intake mailbox. Produce the batch deliverables and update the Intake learning register. End with END OF BATCH B02.

Change the batch number and date every time. Never reuse a batch number.

## New conversation, or the register is not visible

> Here is the latest Intake learning register. Continue from it. Next batch follows.

## Optional check after a batch

> Check batch B02 and the register. List every item without a thread ID, every reason you inferred rather than saw, every personal name or email address, and every code or request type that does not match the register. Then fix them.

## When you have about a month, or have had enough

Attach the latest register and, if you have them, the saved batch files, then send:

> BUILD SKILLS. Using the Intake learning register and the attached batch files, build the skill deliverables in the output format: the front-door skill, one skill for each request type with three or more threads, the knowledge pack, the glossary, our companies by name, the code key for outside parties without names, open questions and the coverage report. Keep each skill set under about 15,000 words and each SKILL.md under about 4,000 words; split skills rather than drop evidence. Start each file with an === FILE: folder/name.md === line. Mark everything status: draft (unverified).
